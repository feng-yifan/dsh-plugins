# dsh-alertmanager

[![](https://img.shields.io/badge/powered_by-dsh-4D6BFE?style=flat-square&logo=deepseek&logoColor=white)](https://github.com/deepseek-ai/deepseek-harness)

**简体中文** | [English](README.en.md)

在 DSH Web 左侧栏加一个 **AlertManager** 主面板：并行读取多个 AlertManager HTTP API v2 实例，把告警聚合为多列卡片；勾选任意条数、选一个 DSH 工作区后点「处理」，就会在该工作区新建会话、写入标题，并把按实例分组的告警上下文作为首条用户消息发给 agent 立即开始处理，界面随后跳到该会话。

## 能力

- **侧栏入口**：图标 + 「AlertManager」+ 分级数量胶囊（严重 / 警告 / 提示 / 其他的计数）。入口挂载即自动拉取一次，不打开面板也能看到数字。
- **多实例**：设置里可添加任意多个实例，每个独立配置名称、地址、鉴权与 TLS 选项；并发拉取，单个实例失败不影响其它实例（失败实例在列表上方单独提示，不阻塞其它实例）。
- **筛选**：搜索（告警名 / 标签 / 注解 / 实例名）+ 状态 + 级别 + 实例，合并为一行胶囊控件，右侧显示当前结果计数。
- **卡片**：严重度色条、实例标签、名称、严重度/状态标签、2 行摘要、单行标签；只有内容确实溢出时才出现「展开」，展开后显示来源外链、全部标签、注解、指纹、静默与抑制来源。
- **选择**：点击卡片即切换选中（拖选文字时不触发）；复选框是键盘可达的控件；不限制单次选择条数。
- **刷新**：Grafana 式两态「刷新 / 取消」。空闲时可以手动刷新，并可选择自动刷新间隔（关闭 / 5s / 10s / 30s / 1m / 5m，默认 5s）；刷新中可取消在途请求并保留上次成功数据。状态行显示倒计时，手动刷新会重置计时；自动刷新是静默的，不会把按钮切成取消态。
- **派发提示词可控**：设置里可选风格 —— 简洁（默认，一句引导语 + 告警名称，如「解决以下 AlertManager 告警：」+ 名称列表）或详细（完整的告警上下文与处理要求）；简洁模式的引导语可自定义（≤500 字符）。
- **状态提示**：无告警且实例全部可达时显示「一切正常」成功态。
- **主题**：颜色、圆角、字号、阴影跟随 DSH 的浅色/暗色主题与用户字号设置。
- 中文 / English 双语界面。

## 安装

```bash
dsh plugin --profile web add dsh-alertmanager
```

装完重启 `dsh web`（新增插件行需要重新组合 profile；只是升级同版本号的话刷新页面就够）。

## 面板内配置

打开左侧栏 **AlertManager** 面板，点右上角「AlertManager 设置」：

| 字段 | 说明 |
| --- | --- |
| 名称 | 必填；新建实例时前端默认取 URL 的 host，后端也会兜底 |
| 地址 | 必填，`http://` 或 `https://` 绝对地址，多个实例的地址不能重复 |
| 鉴权方式 | 无 / Basic / Bearer |
| 用户名 | 仅 Basic 使用 |
| 口令或 token | 仅 Basic / Bearer 使用；留空表示保留该实例已保存的值 |
| 忽略 TLS 证书校验 | 默认否；自签名证书且地址是 https 时使用 |
| 提示词风格 | 简洁（默认）/ 详细，见下文「派发提示词」 |
| 引导语 | 仅简洁模式：消息第一行，插件随后自动列出告警名称（≤500 字符） |

设置保存在 DSH 凭据服务里，不写入 profile 的 `cordis.patch.yml`；读取设置时不会把口令/token 回传给浏览器，只返回 `hasSecret`。

## 派发提示词

派发时发给 agent 的首条消息由设置里的「提示词风格」决定：

- **简洁（默认）**：引导语 + 去重后的告警名称，别无其它。例如：

  ```
  解决以下 AlertManager 告警：
  - MemoryRequestTooLow
  - GitLabBackupStale
  ```

  若有派发时已恢复的告警或不可达实例，末尾会各加一行简短说明。
- **详细**：完整的结构化上下文（工作区路径、按实例分组的告警字段、标签、注解、指纹，以及「处理要求」），总长上限 20000 字符。

两种风格都仍受 20000 字符上限约束；引导语上限 500 字符。

## 行为

点「处理」后，插件会在所选工作区新建会话、写入标题，并把按实例分组的告警内容作为首条用户消息发给 agent，界面随后跳到该会话。prompt 会要求 agent 先只读排查、改动前说明方案、处理完汇报根因 / 操作 / 验证 / 后续建议。

**点「处理」会立即新建会话并消耗一轮模型调用**；请确认工作区与告警内容后再点。

## 限制

- 只支持 AlertManager HTTP API **v2**（`/api/v2/alerts`），不支持 v1。
- 不支持依赖反向代理 Cookie 登录态；需要 Basic / Bearer 或允许匿名读取。
- 不做静默（silence）管理，只读取与派发；单次派发条数不设上限。
- TLS 校验关闭只作用于本插件的 AlertManager 请求，不影响 DSH 自身。
- 侧栏入口的文字标签同时被用作该行按钮的 `aria-label`；为了显示数量胶囊，标签是 React 节点，因此该按钮的 `aria-label` 会退化为 `[object Object]`（视觉正常，读屏体验受影响；如在意可改为纯文本标签）。
